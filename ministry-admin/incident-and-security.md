# 오류 대응과 개인정보 보호

운영 오류는 중복 작업보다 원본 기록 보존과 순서 있는 확인이 중요합니다.

## 대표 상황별 확인 순서

| 상황 | 먼저 확인할 것 |
|---|---|
| 포인트가 다름 | 출석 저장, 최근 지급, 관리자 조정, 상점 주문 |
| EXP만 다름 | 활동별 EXP 기준과 최근 성장 기록 |
| 학생이 검색되지 않음 | 이름, 활성 상태, 부서·반, 출석부 연결 |
| 퀘스트가 안 열림 | 연결 활동의 저장 여부와 주간 기록 |
| 주문이 안 보임 | 포인트 차감 여부, 주문 내역, 재고 상태 |
| 메뉴가 없음 | 로그인 역할, 담당 부서·반, 승인 상태 |

## 감사 로그를 확인할 때

![감사 로그](../images/admin/audit-log.png)

- 예상하지 못한 포인트 조정
- 상품·재고·정책 변경
- 성경 인물 요청 처리 결과
- 이벤트 설정 변경
- 변경한 관리자와 정확한 시간 확인

## 공개하면 안 되는 정보

- 실제 학생의 민감한 개인정보
- 전화번호와 부모 연락처
- 상담·목양 기록
- 비밀번호와 관리자 인증정보
- API 키, 환경변수와 보안 설정값

## 문의할 때 포함할 내용

1. 사용한 화면과 로그인 역할
2. 학생 이름·부서·반
3. 발생한 날짜와 시간
4. 누른 버튼이나 활동 이름
5. 개인정보를 가린 화면 캡처

오류나 궁금한 점은 김환희 강도사에게 문의합니다.

> 여러 학생에게 같은 문제가 생기면 같은 작업을 반복하지 말고 현재 기록을 보존한 뒤 원인을 확인합니다.
