# 오류 대응과 개인정보 보호

운영 오류는 중복 작업보다 원본 기록 보존과 순서 있는 확인이 중요합니다.

## 대표 상황별 확인 순서

| 상황 | 먼저 확인할 것 |
|---|---|
| 포인트가 다름 | 출석 저장, 최근 지급, 관리자 조정, 상점 주문 |
| EXP만 다름 | 활동별 EXP 기준과 최근 성장 기록 |
| 학생이 검색되지 않음 | 이름, 활성 상태, 부서·반, 출석부 연결 |
| 퀘스트가 안 열림 | 연결 활동의 저장 여부와 주간 기록 |
| 주문이 안 보임 | 포인트 차감 여부, 주문 내역, 재고 상태 |
| 메뉴가 없음 | 로그인 역할, 담당 부서·반, 승인 상태 |

## 오류 심각도

| 구분 | 예시 | 대응 |
|---|---|---|
| 즉시 대응 | 개인정보 노출, 권한 오류, 다수 학생의 잘못된 포인트 | 추가 작업 중지 → 화면과 시각 기록 → 운영 책임자 확인 |
| 당일 처리 | 주문·환불 불일치, 학생 연결 오류, 반복 저장 실패 | 원본 기록 확인 → 수정 → 학생 화면 재확인 |
| 일반 문의 | 사용법 질문, 단일 화면 표시 문제 | 새로고침과 역할 확인 후 문의 |

## 공통 복구 원칙

1. 같은 버튼이나 일괄 입력을 반복하지 않습니다.
2. 문제가 생긴 화면, 시각과 대상을 기록합니다.
3. 출석·지급·주문 중 어느 원본에서 시작됐는지 찾습니다.
4. 취소 기능이 있으면 새 조정보다 취소를 우선합니다.
5. 수정 뒤 학생 화면과 감사 로그를 함께 확인합니다.

## 감사 로그를 확인할 때

![감사 로그](../images/admin/audit-log.png)

- 예상하지 못한 포인트 조정
- 상품·재고·정책 변경
- 성경 인물 요청 처리 결과
- 이벤트 설정 변경
- 변경한 관리자와 정확한 시간 확인

## 공개하면 안 되는 정보

- 실제 학생의 민감한 개인정보
- 전화번호와 부모 연락처
- 상담·목양 기록
- 비밀번호와 관리자 인증정보
- API 키, 환경변수와 보안 설정값

## 문의할 때 포함할 내용

1. 사용한 화면과 로그인 역할
2. 학생 이름·부서·반
3. 발생한 날짜와 시간
4. 누른 버튼이나 활동 이름
5. 개인정보를 가린 화면 캡처

### 복사해서 쓰는 보고 양식

```text
[JoyGrow 오류 보고]
- 발생 시각:
- 사용 화면과 로그인 역할:
- 대상 학생의 부서·반·이름:
- 수행한 작업:
- 화면에 나온 문구:
- 이미 다시 시도했는지:
- 개인정보를 가린 캡처 첨부 여부:
```

오류나 궁금한 점은 김환희 강도사에게 문의합니다.

> 여러 학생에게 같은 문제가 생기면 같은 작업을 반복하지 말고 현재 기록을 보존한 뒤 원인을 확인합니다.
